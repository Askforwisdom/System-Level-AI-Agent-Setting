# Register Project

将 Agent 注册到系统用户级 Agent 注册登记表。

## 权限边界（必须先确认）

- 本 skill 只对**工作目录为 `C:/Users/Administrator/.agents` 的会话**生效。只有该会话有权修改注册登记表文件。
- 其他 Agent 的会话（工作目录为其他项目的 Agent）**不得直接注册**，也不得被要求代为注册。若注册请求来自其他 Agent 的会话，应拒绝写入，并引导用户在 .agents 目录会话中发起注册。
- 执行注册前确认：当前工作目录确为 `C:/Users/Administrator/.agents`。否则立即停止并说明边界。

## 注册前检查

1. 确认待注册 Agent 的工作目录真实存在（如 `D:/xxx/project`）。
2. 确认该工作目录根存在自己的 `AGENTS.md`。注册登记表只登记指针，Agent 的使用权限与操作约定以其自身 `AGENTS.md` 为唯一判据；若缺失，先提示用户补齐，或取得用户明确同意后按简化条目注册（条目中说明约束待补充）。
3. 枚举该工作目录 `.agents/skills/`（或其对外的 skill 目录），确认对外能力的 skill 名称与用途；没有对外 skill 的 Agent 一般不注册（无能力可调用的注册没有意义），除非用户明确要求先占位。
4. 读取现有注册登记表 `C:/Users/Administrator/.agents/AGENTS.md`，检查该 Agent 是否已注册：
   - 已注册：不重复追加，改为**更新**原有条目（职责、能力、约束有变化时）。
   - 未注册：在"注册 Agent"小节末尾追加新条目。

## 条目格式

沿用注册登记表既有段落格式，在 `<!-- 后续有新 Agent 要注册时... -->` 注释之前插入：

```markdown
### <Agent 中文名>（<Agent 英文名>）

- **工作目录**：`<绝对路径，正斜杠>`
- **职责**：<一两句话说明该 Agent 管什么、收录什么>
- **对外能力**：
  - <能力描述>（skill：`skill-name`，<必要的触发条件或限制>）
- **约束**：本 Agent 的使用权限与操作约定（<约束要点列举>）**以 `<工作目录>/AGENTS.md` 为准**；使用前须按"使用约定"第 2 条引导 subagent 加载该文件并严格遵循其中的约束。
```

编写要求：

- 工作目录用绝对路径、正斜杠，与既有条目风格一致。
- 对外能力逐条列出 skill 名称；没有 skill 承载的能力也可写成纯描述（如"查询 XX 数据源"），但须说明调用方式。
- 约束条目是固定句式，指向该 Agent 工作目录下自身 `AGENTS.md`，不在注册登记表中复制其内部规则细节。

## 不修改的部分

注册动作**只追加/更新"注册 Agent"小节下的条目**，以下内容保持原样：

- "使用约定"（subagent 派发与引导模板）。
- 其他 Agent 的既有条目（除非本次任务就是更新它）。

## 验证

完成后检查：

- 新条目格式与既有条目一致（标题层级、加粗字段、缩进）。
- 条目中的工作目录、skill 名称与该 Agent 实际工作目录中的文件相符。
- 注册登记表其余部分无改动（可用 `git diff` 或前后对比确认）。
- 向用户回显新增/更新的条目内容，说明注册完成。
