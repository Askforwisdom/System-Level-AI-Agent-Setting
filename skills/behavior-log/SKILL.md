# Behavior Log（项目 Agent 行为日志）

记录项目 Agent 在会话中的每次行为及结果。

## 核心原则

- 重点记录行为中的报错、失败、异常和使用问题，包括流程繁琐、工具缺失、文档不清、约定冲突等情况。
- 遵循目标项目 Agent 根目录中的 `AGENTS.md` 及其他适用说明；项目 Agent 已有的行为日志约定与本规范冲突时，以项目 Agent 的约定为准。

## 记录时机

- 项目 Agent 的任何行为完成、暂停或失败后必须记录。
- 日志成功写入后方可报告任务完成；写入失败时须如实报告。

## 日志位置与格式

- 先确定本次行为归属的目标项目 Agent 根目录；多项目场景以行为实际发生的项目 Agent 为准。
- 日志固定保存在 `<目标项目 Agent 根目录>/.agents/behavior/log/`，每个自然月使用一个 `YYYY-MM.md` 文件；目录不存在时直接创建。
- 路径按完整层级拼接。目标项目 Agent 根目录本身名为 `.agents` 时，仍在其下使用 `.agents/behavior/log/`；例如根目录为 `C:/Users/<用户名>/.agents` 时，日志目录为 `C:/Users/<用户名>/.agents/.agents/behavior/log/`。

使用以下结构创建月度日志：

```markdown
# YYYY 年 MM 月项目 Agent 行为日志

| 发生时间 | 项目 Agent 行为 | 执行结果 | 备注 |
|---|---|---|---|
| YYYY-MM-DD HH:mm | <简略行为描述> | <结果> | <说明：遇到的错误与使用问题在此说明> |
```

## 追加规则

- 优先使用 Agent 的文件编辑工具（如 `apply_patch`）在文件末尾追加日志，保留已有内容；写入后读取验证。避免使用已知会触发透明加密问题的命令写入方式。
- 每次行为均按实际发生时间在表格末尾新增记录；同一行为再次发生时仍作为新的行为记录。
- 更正已有记录时，将更正作为新的行为追加，并说明对应的原记录；原记录保持不变。
- 行为暂停或失败时，在执行结果或备注中说明原因和关键错误；行为成功但发现使用问题时，在备注中说明具体问题。
- 补录历史行为时，在表格末尾新增记录，填写该行为的实际发生时间；只补录能够从现有资料中验证的内容。

## 错位日志处理

- 发现 `<目标项目 Agent 根目录>/behavior/log/` 等非规范位置的日志时，将记录合并至规范路径；只跳过内容完全相同的同一记录副本，相同行为再次发生形成的记录全部保留。确认记录完整后清理错位文件，并记录迁移过程。

## 验证

写入后检查：

- 日志位于 `<目标项目 Agent 根目录>/.agents/behavior/log/YYYY-MM.md`。
- 新记录位于表格末尾且字段完整；行为中的错误与使用问题已说明（如有）。
- 处理错位日志时，同一记录副本已去重，其他记录完整保留，错位文件已清理。
