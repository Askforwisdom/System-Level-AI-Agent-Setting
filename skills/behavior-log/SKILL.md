# Behavior Log（项目行为日志）

将 Agent 的所有行为记录到项目月度行为日志。项目只有这一种行为日志。

## 核心原则

- 记录 Agent 的**所有**简略行为信息——查询、修改、维护、临时操作等，不限行为类型。
- **重点收集错误信息与使用不便信息**：行为执行中遇到的报错、失败、异常，以及使用过程中发现的不便（流程繁琐、工具缺失、文档不清、约定冲突等），必须在日志中明确体现，这是日志最重要的价值之一。
- 日志只记录简略的行为信息和结果；产出文件在备注中体现。
- 保留全部历史日志；更正记录时以新增更正说明的方式进行。
- 遵循项目中的 `AGENTS.md` 及其他适用说明；项目已有的行为日志约定与本规范冲突时，以项目约定为准。

## 记录时机

- Agent 的任何行为完成、暂停或失败后必须记录。
- 日志成功写入后方可报告任务完成；写入失败时须如实报告。

## 日志位置与格式

- 日志保存在 Agent 工作目录（项目目录）下的 `.agents/behavior/log/`，每个自然月使用一个 `YYYY-MM.md` 文件；目录不存在时直接创建。
- 月份根据项目采用的时区确定。

使用以下结构创建 `.agents/behavior/log/YYYY-MM.md`：

```markdown
# YYYY 年 MM 月项目行为日志

| 发生时间 | Agent 行为 | 执行结果 | 备注 |
|---|---|---|---|
| YYYY-MM-DD HH:mm | <简略行为描述> | <结果> | <说明：涉及产出文件时在此给出路径；遇到的错误信息、使用不便信息也在此说明> |
```

## 追加规则

- 向现有表格末尾追加记录，已有日志保持原样。
- 同一行为可能重复执行时，使用发生时间区分。
- 发生时间和行为均与已有记录相同时，视为已记录。
- 行为暂停或失败时，记录结果和原因，并写明关键错误信息。
- 行为过程中发现使用不便（即使行为本身成功），也须记录行为并在备注中说明不便之处。
- 更正记录时新增一条更正说明。
- 只补录能够从现有资料中验证的历史行为。

## 验证

写入后检查：

- 日志文件名符合 `YYYY-MM.md`。
- 新记录追加在表格末尾，历史记录保持原样。
- 记录字段完整（发生时间、Agent 行为、执行结果）。
- 行为过程中的错误信息与使用不便信息已记录（如有）。
- 产出文件体现在备注列中。
- 写入失败时已如实报告。
