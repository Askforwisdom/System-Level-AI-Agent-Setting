# Skill 文本表述规范

skill 的文本（description、正文、模板）建议参考以下表述约定，保持各 skill 风格一致、语气统一。本规范自身也按这些约定撰写。

## 表述约定

1. **引导优先**。规则宜用引导、缓和类修饰词表述（建议、一般、可、推荐、引导）；像"只允许……""唯一入口""不得……""严禁……"这类强制与否定叠加的强调，建议改为引导式说法（如"建议统一经由……""一般由……"）。
2. **规则不重复强调**。同一限制不宜用"正面允许 + 反面禁止"两遍强调；跨文件涉及同一约定时，一处表述即可，其余处以指针指向（如"以该 skill 为准"）。
3. **正向表述**。优先说明应当怎么做；单条操作纪律可直接简明陈述（如"不要……"式短句），不必叠加"必须/唯一/只有"类强制修饰。
4. **术语统一**。行为主体是 Agent，宜写"Agent 行为"等说法，避免"项目行为"这类易把行为主体误读为项目的表述；同一概念在同一 skill 及关联文件中使用同一术语。
5. **简明直接**。规则陈述条件与动作即可，同义强调宜删繁就简；模板、列头、清单等格式内容与既有 skill 保持一致风格。

## 参考示例

| 强调式表述 | 引导式表述 |
|---|---|
| 本 skill 是唯一写入入口，仅可在 X 会话中执行写入 | 写入建议统一经由本 skill 进行，一般由 X 会话执行 |
| 其他 Agent 的会话不得直接注册，应拒绝写入 | 来自其他会话的注册请求，建议引导用户回到本目录会话中发起 |
| 以其自身 AGENTS.md 为唯一判据 | 以其自身 AGENTS.md 为准 |
| 项目只有这一种行为日志 | （删除，存放位置一节已说明） |
